    Guillermo Rauch 发布 𝚡𝚎𝚎𝚝，一个用 safe Rust / wasm 写的封闭式 X 帖子渲染器，零浏览器、零网络、零文件系统、零系统字体，约 1ms 渲染成 PNG，比启动浏览器截图快 100 倍到 1000 倍，同时复现 Blink 与 HarfBuzz 的文字整形、1/64px 换行、RTL 双向文本、28 个 Chirp 字体子集与 CJK/数学/emoji 回退。它被组织成 autorepo：一个 oracle 启动 Chrome 验证数万条排版规则，CI canary 跟踪上游演化并提交签名 PR 供 agent 处理，整体围绕“验证工程”设计。他另提到 AI 模型起名能力已经很强，自己写的诊断 CLI 被命名为 𝚑𝚘𝚐。

    Guillermo Rauch introduced 𝚡𝚎𝚎𝚝, a hermetic, pixel-perfect X post renderer in safe Rust / wasm with zero browser, network, filesystem, or system fonts, rendering a post to PNG in about 1ms (0.4 ms for Jack Dorsey's "setting up my twttr"). He said rendering with xeet is 100x-1000x faster than booting a browser for a screenshot while staying just as accurate, reproducing Blink & HarfBuzz text shaping, 1/64px line breaking, RTL bidi, 28 Chirp font subsets, CJK/Math/Emoji fallbacks, and "Show more" rules. Rauch described it as structured as an "autorepo": an oracle boots Chrome to verify tens of thousands of text layout rules, and a CI canary watches the original and files signed PRs for agents to act on, conceived around "verification engineering." He also noted AI models are getting good at naming things, citing a CLI for diagnosing system slowdowns it named 𝚑𝚘𝚐.

  15. 11.10Nov 10周二Tue查看本期View issue

    Guillermo Rauch 非常看好 MCP，认为它的价值超出“M”本身，即使抛开 AI，让所有系统通过一个通用开放协议通信也是文明级成就。他指出缺失的一环是跨会话的任意回调，MCP 能读能写却无法事后通知“这个事件发生了”，MCP Events 补上了这一点：agent 发起部署后可以订阅 `deployment.succeeded` 而不是轮询。他还说 Vercel 在发布前测试了新模型，结论是“惊人地聪明”，新一代模型能承接前所未有的并行工作，瓶颈变成野心和并行算力，用 Vercel CLI 加 `/offload-to-sandbox` 技能即可按需分配云沙箱。

    Guillermo Rauch is bullish on MCP, arguing its utility exceeds the "M" part as a universal open protocol. The missing piece was arbitrary callbacks across sessions, so MCP Events lets an agent subscribe to something like 𝚍𝚎𝚙𝚕𝚘𝚢𝚖𝚎𝚗𝚝.𝚜𝚞𝚌𝚌𝚎𝚎𝚍𝚎𝚍 instead of polling, with support coming to Vercel's own MCP.
